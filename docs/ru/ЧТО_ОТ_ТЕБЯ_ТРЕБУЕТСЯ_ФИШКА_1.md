## Уровень 1 — Минимум: проверка по базе и счётчик

**Результат:** «Проверить канал» отвечает по каналам из **scam_base**; на главной работают блок LIVE и форма «Сообщить о разводе».

### Что сделать тебе

1. **Google: доступ к таблице**
   - Зайти в [Google Cloud Console](https://console.cloud.google.com) → свой проект.
   - Включить **Google Sheets API** (APIs & Services → Library → Google Sheets API).
   - Создать **сервисный аккаунт** (Credentials → Create Credentials → Service account), скачать **JSON-ключ**.
   - В твоей таблице: **Поделиться** → добавить email из JSON (поле `client_email`) с правом **Редактор**.

2. **Переменные на Render (Environment)**
   - `KRO_SHEET_ID` = `1C1NQwqmLRg59xgplnz5PeghRxaR_YY2lfSWZAJae6qM`
   - `KRO_GOOGLE_CREDENTIALS_JSON` = весь JSON сервисного аккаунта **одной строкой** (без переносов).
   - `KRO_SCAM_BASE_RANGE` = `scam_base!A2:H`
   - (по желанию) `KRO_CHECK_QUEUE_RANGE` = `check_queue!A2:B` — если потом включишь воркер.

3. **Лист scam_base**
   - В таблице на листе **scam_base** должна быть хотя бы одна строка с каналом (колонки A–H: username, risk_score, ads_per_week, bot_pct, vip_price, complaints, total_loss, verdict). Заголовок в первой строке, данные со второй.

После этого: деплой на Render, заход на сайт → «Проверить канал» по каналу из scam_base должен вернуть риск и вердикт; LIVE и форма жалоб — брать данные из первого листа (Отчёты).

- Первый лист таблицы должен иметь колонки: **Дата | канал | сумма ₽ | тип | статус | от кого** (заголовок в строке 1, данные с A2). У тебя так и есть.

Ничего дополнительно настраивать не нужно — бэкенд читает и пишет в первый лист по умолчанию.

## Уровень 3 — Живая проверка: любой канал без «не найден в базе»

**Результат:** пользователь вводит любой канал (ник, t.me, invite) → один запрос → сразу оценка риска (без обязательного «подождите 1–2 минуты»), если на сервере работает Telethon. Либо канал попадает в очередь, и воркер через 1–2 минуты дописывает результат в scam_base.

### Вариант А: живая проверка на Render (сразу в ответе)

**Что сделать тебе:**

1. **Telegram API**
   - Зайти на https://my.telegram.org → API development tools → создать приложение (если ещё нет).
   - Скопировать **API ID** и **API Hash**.

2. **Переменные на Render**
   - Добавить: `TELEGRAM_API_ID` (число), `TELEGRAM_API_HASH` (строка).

3. **Сессия Telethon на Render**
   - На Render обычно **нельзя** интерактивно ввести код из Telegram. Поэтому либо:
     - один раз сгенерировать сессию **локально** (см. `backend/kro-worker/ВХОД_ПО_QR.md` или `СЕССИЯ_ИЗ_TELEGRAM_DESKTOP.md`), затем положить файл `kro_worker.session` в `backend/kro-worker/` и **не коммитить** (на Render тогда нужно использовать секрет/артефакт сборки, что сложно),  
     - **либо** использовать вариант Б (воркер у себя).

На практике на Render проще использовать **вариант Б** (воркер на твоём ПК или VPS).

### Вариант Б: воркер на твоём компьютере (рекомендуется)

**Что сделать тебе:**

1. **Переменные на Render** — как в уровнях 1–2. Плюс задать `KRO_CHECK_QUEUE_RANGE=check_queue!A2:B`, чтобы при отсутствии канала в базе бэкенд добавлял его в очередь.

2. **На своём ПК (или VPS)**
   - Установить Python 3, перейти в `backend/kro-worker/`.
   - Создать файл **`env`** из `.env.example`, заполнить:
     - `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` (с my.telegram.org),
     - `KRO_SHEET_ID=1C1NQwqmLRg59xgplnz5PeghRxaR_YY2lfSWZAJae6qM`,
     - `KRO_SCAM_BASE_RANGE=scam_base!A2:H`, `KRO_CHECK_QUEUE_RANGE=check_queue!A2:B`,
     - доступ к Google: либо `KRO_GOOGLE_CREDENTIALS_JSON`, либо `credentials.json` + `GOOGLE_APPLICATION_CREDENTIALS`.
   - Один раз войти в Telegram (сессия):
     - `python login_via_qr.py` или по инструкции в `СЕССИЯ_ИЗ_TELEGRAM_DESKTOP.md` — в итоге должен появиться файл `kro_worker.session`.
   - Запускать воркер в фоне, например:  
     `./run_worker_loop.sh`  
     или вручную раз в минуту: `python worker.py`. Воркер читает **check_queue**, проверяет канал через Telethon и дописывает строку в **scam_base**.

3. **Поведение для пользователя**
   - Пользователь вводит канал → если его нет в scam_base, бэкенд добавляет в check_queue и пишет: «Проверяем канал по Telegram. Подождите 1–2 минуты и нажмите «Проверить» снова».
   - Через 1–2 минуты воркер обрабатывает очередь, канал появляется в scam_base.
   - Пользователь снова нажимает «Проверить» — получает результат.

Подробно: `backend/kro-worker/README.md`, `docs/ru/10_KRO_ТЕЛЕГРАМ_НАСТРОЙКА_И_ДРУГОЙ_КОМПЬЮТЕР.md`.

## Приступаем: шаги после того, как Google настроен

Если ты уже сделала таблицу, сервисный аккаунт и «Поделиться» — делаем по порядку.

### 1. Проверить подключение к таблице локально

В корне проекта должен быть файл `.env` с переменными (как в `.env.example`). Затем:

```bash
cd "Documents/Crypto academy pro/crypto-academy-pro1"
node backend/scripts/verify-kro-google.js
```

Скрипт прочитает первый лист и **scam_base**. Если всё ок — увидишь `✅ Подключение к таблице работает`. Если ошибка доступа — снова открой таблицу → «Поделиться» → добавь email из JSON (поле `client_email`) с правом **Редактор**.

### 2. Переменные на Render

В панели Render → твой сервис (crypto-academy-pro) → **Environment** добавь или проверь:

| Переменная | Значение |
|------------|----------|
| `KRO_SHEET_ID` | `1C1NQwqmLRg59xgplnz5PeghRxaR_YY2lfSWZAJae6qM` |
| `KRO_GOOGLE_CREDENTIALS_JSON` | Весь JSON сервисного аккаунта **одной строкой** (скопировать из файла, без переносов) |
| `KRO_SCAM_BASE_RANGE` | `scam_base!A2:H` |
| `KRO_CHECK_QUEUE_RANGE` | `check_queue!A2:B` (нужно для очереди/воркера; можно добавить позже) |

После сохранения Render сделает новый деплой.

### 3. Лист scam_base в таблице

В твоей Google-таблице открой лист **scam_base**. Должны быть:

- Строка 1: заголовки `username` | `risk_score` | `ads_per_week` | `bot_pct` | `vip_price` | `complaints` | `total_loss` | `verdict`
- Хотя бы одна строка 2 с каналом, например: `@TONPumpElite` | `87` | `14` | `78%` | `7000₽` | `23` | `2.1млн₽` | `scam`

Если строк с данными нет — добавь одну вручную (можно взять пример из твоего листа «Отчёты»: канал из колонки B подставить в scam_base).

### 4. Проверка на сайте

После деплоя открой сайт (например https://crypto-academy-pro.onrender.com):

1. Блок **«Проверить канал»** — введи канал, который есть в scam_base (например `@TONPumpElite`), нажми «Проверить». Должны появиться риск, причины, потери, вердикт.
2. Блок **LIVE** — цифры «каналов за день», «потеряно», «Топ-3» подтягиваются из первого листа (Отчёты).
3. **«Сообщить о разводе»** — заполни канал и сумму, отправь. В первом листе таблицы должна появиться новая строка.

Если «Проверить канал» пишет «Не настроена база каналов» — на Render не заданы `KRO_SHEET_ID` или `KRO_GOOGLE_CREDENTIALS_JSON`, либо деплой ещё не обновился. Подожди 1–2 минуты после сохранения Environment и обнови страницу.
