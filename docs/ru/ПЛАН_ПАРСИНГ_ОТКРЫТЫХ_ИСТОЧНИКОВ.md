# План: парсинг открытых источников для цифр на главной

Путь: скрипты парсят открытые сайты и (опционально) Telegram, обновляют данные без ручного ввода.

---

## 1. Источники (URL и что с них берём)

| Источник | URL | Что парсим | Частота |
|----------|-----|------------|---------|
| **Vklader — чёрный список** | https://vklader.com/blacklist-telegram/ | Количество каналов/никнеймов (@username, t.me/…), дата обновления списка («Список обновлён ДД.ММ.ГГ») | 1 раз в сутки |
| **TGRev — скам-каналы** | https://tgrev.ru/scam-telegram-channel | Количество каналов в чёрном списке (ссылки на /channels/@...) | 1 раз в сутки |
| **Telegram (опционально)** | Канал «База SKAM» (@baza_scam4kov) и/или свои чаты | Количество постов/жалоб за день, упоминания сумм (сложнее, нужен Telethon) | По желанию, 1 раз в 6–12 ч |

**Итоговые метрики для главной:**
- **«новых скам‑каналов за день»** — либо разница «было вчера / стало сегодня» по vklader/tgrev, либо число новых записей за сутки (если сайты отдают даты).
- **«Telegram каналов»** — суммарное количество каналов в списках (vklader + tgrev, без дублей по @username).
- **«Потеряно ₽»** — из открытых списков почти не извлекается; оставляем оценку из отчётов или ноль, либо подключаем парсинг отзывов/жалоб (отдельная задача).
- **«Курсы фейк-продуктов»** — можно считать упоминания «курс», «марафон», «VIP» на странице vklader и завести отдельный счётчик (оценка).

## 2. Правила обхода (чтобы не забанили и не нарушать правила)

- **robots.txt** — перед написанием скрипта проверить для vklader.com и tgrev.ru. Не ходить по путям, запрещённым в robots.txt.
- **Задержки:** не чаще 1 запроса в 3–5 секунд на один домен; между разными доменами — минимум 2 секунды.
- **User-Agent:** выдавать себя за обычный браузер, например:  
  `Mozilla/5.0 (Windows NT 10.0; rv:91.0) Gecko/20100101 Firefox/91.0`
- **Объём:** только нужные страницы (1–2 URL на сайт в один запуск), без глубокого обхода и без перебора сотен страниц.
- **Cron:** запуск скрипта не чаще 1 раза в 6 часов (рекомендуется 1 раз в сутки, например в 06:00 MSK).

## 3. Куда писать результат

**Вариант A (рекомендуется для старта):** обновлять файл `backend/data/kro-reference-stats.json`.

- Скрипт после парсинга перезаписывает JSON: `channelsToday`, `telegramCount`, `coursesCount` (и при возможности `totalLost`).
- Бэкенд уже читает этот файл при пустой/недоступной таблице — ничего в API менять не нужно.
- Плюс: не нужен доступ к Google, один файл на диске, подходит для cron на любом хостинге.

**Вариант B:** дописывать строки в Google Таблицу (лист отчётов A:F).

- Каждый «новый» канал за день — одна строка: дата, @username, 0 или оценка потерь, тип «Парсер», статус «Активен», источник (vklader/tgrev).
- Нужны те же credentials, что и для бэкенда (KRO_SHEET_ID, сервисный аккаунт).
- Плюс: главная тогда показывает «реальные» данные из таблицы; минус — нужна настройка доступа и лимиты записи в API.

**Комбо:** скрипт обновляет JSON (всегда) и опционально пишет новые каналы в таблицу (если заданы переменные окружения для Sheets).

## 4. Где запускать скрипт (хостинг и cron)

| Вариант | Плюсы | Минусы |
|---------|--------|--------|
| **Локально (cron)** | Полный контроль, бесплатно | Компьютер должен быть включён в момент запуска |
| **Render Cron Job** | Уже есть бэкенд на Render, один репозиторий | Нужно настроить Cron Job и передать env (путь к JSON через volume или запись в репозиторий — обычно только чтение) |
| **GitHub Actions** | Бесплатно, не нужен свой сервер | Нет постоянного диска — результат нужно куда-то отправить (API вашего бэкенда или коммит в репо; коммит усложняет историю) |
| **Railway / другой PaaS** | Удобный cron, можно хранить файл в volume | Отдельный сервис или тот же бэкенд с cron |

**Рекомендация:** сначала запускать скрипт **локально по cron** (раз в сутки), писать результат в `backend/data/kro-reference-stats.json`. Если проект уже на Render — добавить **Cron Job**, который раз в день дергает скрипт; скрипт пусть отдаёт результат в ваш бэкенд (новый эндпоинт `POST /api/kro/ingest-parsed` обновляет JSON в памяти/диске или пишет в таблицу).

## 5. Что нужно от вас перед реализацией

1. **Подтверждение источников:** разрешаете парсить только публичные страницы vklader.com и tgrev.ru (1–2 запроса в день на домен), с задержками и нормальным User-Agent. Если нужно, позже добавим Telegram (Telethon).
2. **Куда писать:** только JSON, только таблицу, или оба (сначала JSON — сделаем так).
3. **Где запускать:** локально (cron), Render Cron Job, GitHub Actions или другой вариант. От этого зависит, как скрипт будет сохранять результат (локальный файл vs запрос к API).
4. **Telegram:** нужно ли на первом этапе парсить канал «База SKAM» или другие (тогда понадобятся API ID, API Hash, сессия Telethon, как для check_once).

## 6. Этапы реализации (после вашего ответа)

**Этап 1 (без Telegram)**  
- Скрипт (Node.js или Python): загрузка vklader + tgrev, парсинг количества каналов (и при возможности «курсов»/марафонов), запись в `kro-reference-stats.json`.  
- Проверка robots.txt, задержки 3–5 сек.  
- Запуск вручную и по cron 1 раз в сутки.

**Этап 2 (опционально)**  
- Запись в Google Таблицу (новые каналы за день как строки в лист отчётов).  
- Или приём результата по API бэкенда (`POST /api/kro/ingest-parsed`), бэкенд обновляет JSON или таблицу.

**Этап 3 (опционально)**  
- Парсинг Telegram (Telethon): канал «База SKAM», подсчёт постов/жалоб за день, извлечение сумм из текста — отдельная задача с учётом лимитов API и правил использования.
