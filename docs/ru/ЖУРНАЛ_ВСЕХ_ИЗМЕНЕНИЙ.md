# Журнал всех изменений сайта

**Назначение:** сюда записывается **каждое** изменение сайта (дизайн, вёрстка, бэкенд, скрипты, конфиг, документация, контент). Так мы всегда видим, что и когда менялось, и при необходимости можем вернуться в прошлое (по git + этой записи).

---

## Правило: любые изменения записываются

1. **Перед или сразу после правки** в коде/конфиге/документации — добавляется запись в этот журнал.
2. **Формат записи:** дата, категория, затронутые файлы, что сделано, при возможности — hash коммита (например `86bf641`).
3. **Категории:** `дизайн/вёрстка` | `бэкенд` | `скрипты` | `конфиг` | `документация` | `контент` | `деплой`.
4. Детали по правкам **дизайна и вёрстки** (селекторы, зоны) ведут в [ЖУРНАЛ_ИЗМЕНЕНИЙ_ДИЗАЙНА.md](./ЖУРНАЛ_ИЗМЕНЕНИЙ_ДИЗАЙНА.md); здесь — кратко и ссылка на зону при необходимости.
5. Текущее состояние сайта «как есть» описано в [ТЕХНИЧЕСКИЙ_СНАПШОТ_САЙТА.md](./ТЕХНИЧЕСКИЙ_СНАПШОТ_САЙТА.md). После крупных изменений снапшот можно обновить и зафиксировать это отдельной записью здесь.

---

## Формат одной записи

```text
### ГГГГ-ММ-ДД | Категория
- **Файлы:** путь/к/файлу (несколько через запятую)
- **Что сделано:** краткое описание (что изменено, зачем)
- **Коммит:** hash (если уже запушено)
- **Примечание:** ссылка на зону/другой документ при необходимости
```

## Как возвращаться в прошлое

1. **По журналу:** найти запись по дате/описанию, посмотреть список файлов и коммит.
2. **В git:** `git log --oneline`, при необходимости `git show <hash>` или `git checkout <hash> -- путь/к/файлу` для восстановления конкретного файла.
3. **По снапшоту:** открыть [ТЕХНИЧЕСКИЙ_СНАПШОТ_САЙТА.md](./ТЕХНИЧЕСКИЙ_СНАПШОТ_САЙТА.md) и сверить текущую структуру/API/зоны с описанной — так видно, что именно менялось со времени снапшота.
