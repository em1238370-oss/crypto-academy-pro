# Что нужно, чтобы цифры на главной брались из интернета

Вы хотите, чтобы «новых скам‑каналов за день», «Потеряно ₽», «Telegram каналов», «Курсы фейк-продуктов» и топ‑3 были **реальными** — из открытых источников, отзывов, баз скам‑каналов, а не придуманными.

Ниже — что уже сделано и что нужно для полной автоматизации.

---

## Что уже сделано

1. **Оценочные данные из отчётов**  
   В проекте есть файл `backend/data/kro-reference-stats.json` с числами, взятыми из открытых отчётов:
   - **Chainalysis 2025**: ~$17 млрд потерь от криптоскамов в год, ~$46,6 млн в день глобально; доля рублёвого сегмента пересчитана в рублях.
   - **F6, OKX**: рост атак через Telegram (2000%), кражи аккаунтов (8 175+ в день по одной группе), русскоязычные скам‑каналы.
   - **Чёрные списки**: vklader.com, tgrev.ru, каналы типа «База SKAM» — десятки каналов в открытых списках.

   Когда таблица Google не настроена или пуста, сервер отдаёт эти оценки и подпись: «Оценка по открытым отчётам (Chainalysis 2025, F6, OKX)…». На главной показываются именно они.

2. **Таблица — источник истины**  
   Как только вы настраиваете Google Таблицу (KRO_SHEET_ID, лист отчётов A:F) и добавляете туда строки (с сайта, из формы, из бота), на главной показываются **ваши** реальные цифры из таблицы.

3. **Обновление каждые 10 минут**  
   Главная страница сама запрашивает `/api/kro/live-counter` раз в 10 минут, поэтому цифры обновляются без перезагрузки.

---

## Что нужно для полной автоматизации «из интернета»

Чтобы числа **сами** подтягивались из интернета (без ручного ввода в таблицу), нужен один из вариантов ниже.

### Вариант 1: Платные/закрытые API

- **Chainalysis** (Investigations API, Sanctions Screening API) — даёт данные по адресам, сделкам, санкциям. Нужен контракт и API‑ключ. Подходит для ончейн‑потерь и рисков, но не даёт «сколько скам‑каналов за сегодня» в готовом виде.
- **Crystal (Bitfury)** — AML/блокчейн‑аналитика. Аналогично, по запросу и контракту.

**Что нужно от вас:** доступ к API (логин/ключ), решение, какие метрики брать (например, объём потерь за сутки по определённым тегам).

### Вариант 2: Парсинг открытых источников

- **Чёрные списки**: vklader.com, tgrev.ru — списки скам‑каналов. Можно раз в день запускать скрипт, который парсит страницы (с учётом правил сайтов и robots.txt), считает новые за сутки и дописывает строки в Google Таблицу или в свою БД.
- **Telegram**: через Telethon/API можно считать каналы по ключевым словам (VIP, сигналы, гарантия прибыли), но «скам или нет» и «сумма потерь» из интернета в готовом виде не выдаются — только по отзывам/базам.

**Что нужно от вас:** хостинг или cron для скрипта (например, раз в сутки), при необходимости — прокси/учётка, если сайты ограничивают доступ.

### Вариант 3: Свой сбор отзывов и жалоб

- Форма на сайте и бот уже пишут в таблицу.
- Дополнительно можно: парсить чаты/каналы «жертвы», «скам», «развод» (если есть доступ и правила использования), вытаскивать суммы и ники и добавлять их в таблицу скриптом.

**Что нужно от вас:** список чатов/источников, доступ (токен/сессия), формат хранения (та же таблица или отдельная БД).

### Вариант 4: Ручное обновление оценок из отчётов

- Раз в квартал/год выходят отчёты (Chainalysis, F6, другие). Можно вручную обновлять `backend/data/kro-reference-stats.json` (поля `channelsToday`, `totalLost`, `telegramCount`, `coursesCount`) и при необходимости подпись `sourceCaption`. Тогда при пустой таблице на главной будут актуальные оценочные цифры из отчётов.

**Что нужно от вас:** только обновлять JSON по данным из отчётов.

---

## Итог

- **Сейчас:** при пустой таблице показываются оценки из отчётов (Chainalysis, F6, OKX); при заполненной таблице — ваши реальные данные из неё.
- **Чтобы всё «само» бралось из интернета:** нужен либо платный API (Chainalysis и т.п.), либо скрипты парсинга открытых источников и/или Telegram, плюс хостинг/cron и ваши решения по источникам и доступу.

Если напишете, какой вариант вам ближе (API, парсинг, свои чаты, ручное обновление), можно расписать пошаговый план под него.
