# Что сделать, чтобы полная проверка канала работала

Пошаговый список. Отмечай по мере выполнения.

---

## Шаг 1. Ключи Telegram (риск, причины, боты)

1. Зайди на **https://my.telegram.org** (войди по номеру телефона).
2. Открой **API development tools**.
3. Создай приложение (если ещё нет): укажи название, короткое имя — получишь **API ID** (число) и **API Hash** (строка).
4. Скопируй оба значения.

**Куда вписать:**
- **Локально:** открой файл **`.env`** в корне проекта. Добавь (или замени) строки:
  ```env
  TELEGRAM_API_ID=твоё_число
  TELEGRAM_API_HASH=твоя_строка
  ```
- **На Render:** сервис → **Environment** → добавь переменные `TELEGRAM_API_ID` и `TELEGRAM_API_HASH`.

---

## Шаг 2. Google-таблица (потери, база каналов)

1. Таблица у тебя уже есть (ID в .env.example: `1C1NQwqmLRg59xgplnz5PeghRxaR_YY2lfSWZAJae6qM`). Убедись, что в ней есть листы: **первый = Отчёты**, **scam_base**, **check_queue**.
2. Зайди в **Google Cloud Console** (console.cloud.google.com) → свой проект → **APIs & Services** → **Credentials**.
3. **Create Credentials** → **Service account** → создай аккаунт, скачай **JSON-ключ**.
4. Открой JSON: скопируй **весь** его (одной строкой, без переносов — можно вставить в блокнот и сохранить в одну строку).
5. В **таблице** нажми **Поделиться** → добавь email из JSON (поле **client_email**) с правом **Редактор**.

**Куда вписать:**
- **Локально:** в **`.env`**:
  ```env
  KRO_SHEET_ID=1C1NQwqmLRg59xgplnz5PeghRxaR_YY2lfSWZAJae6qM
  KRO_GOOGLE_CREDENTIALS_JSON={"type":"service_account","project_id":...}
  ```
  (весь JSON в одну строку после знака `=`).
- **На Render:** в **Environment** добавь `KRO_SHEET_ID`, `KRO_GOOGLE_CREDENTIALS_JSON`, `KRO_SCAM_BASE_RANGE=scam_base!A2:H`, при необходимости `KRO_CHECK_QUEUE_RANGE=check_queue!A2:B`.

## Шаг 3. Вход в Telegram один раз (сессия)

Без этого шага риска, причин из постов и ботов не будет — скрипт не может читать каналы.

1. В корне проекта убедись, что в **`.env`** уже есть `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` (шаг 1).
2. Установи зависимости для Python-скрипта (один раз):
   ```bash
   cd "/Users/macmini/Documents/Crypto academy pro/crypto-academy-pro1/backend/kro-worker"
   pip3 install -r requirements.txt
   ```
3. Войди в Telegram (из **корня проекта**):
   ```bash
   cd "/Users/macmini/Documents/Crypto academy pro/crypto-academy-pro1"
   node scripts/kro-login.js
   ```
4. Введи **номер телефона** в формате +79... и **код из приложения Telegram** (5 цифр), когда попросит.
5. Проверь: в папке `backend/kro-worker/` должен появиться файл **`kro_worker.session`**. Его не коммитить в git.

Если `node scripts/kro-login.js` ругается на отсутствие Python или скрипта — можно войти так:
```bash
cd "/Users/macmini/Documents/Crypto academy pro/crypto-academy-pro1/backend/kro-worker"
python3 login_telegram.py
```
(переменные `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` должны быть в окружении или в файле `env` в этой папке).

## Шаг 4. Проверка локально

1. Запусти бэкенд из корня проекта:
   ```bash
   cd "/Users/macmini/Documents/Crypto academy pro/crypto-academy-pro1"
   node backend/server.js
   ```
2. Открой в браузере сайт (например http://localhost:4000).
3. В блоке «Проверить канал» введи ссылку на любой канал (например `@durov` или `t.me/какой-то-канал`) и нажми **Проверить**.
4. Должны появиться: **риск**, **причины** (реклама X постов/нед, боты, VIP), **потери** (если есть жалобы в таблице), **вердикт**, **боты**. Если видишь «Сначала один раз войдите в Telegram» — сессии нет, повтори шаг 3.

---

## Шаг 5. Render (сайт в интернете)

- В **Environment** на Render добавь все переменные из шагов 1 и 2 (`KRO_*`, `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`).
- **Важно:** на Render нельзя ввести код из Telegram в консоль. Поэтому **живая проверка по Telegram** (риск, причины, боты) там будет работать только если ты как-то загрузишь уже созданный у себя файл `kro_worker.session` в среду Render (через секрет/артефакт — это отдельная настройка). Иначе на продакшене будут работать только база (scam_base), жалобы и потери из таблицы и превью с t.me; полный разбор по постам — при запуске бэкенда у себя локально или на своём VPS с сессией.
