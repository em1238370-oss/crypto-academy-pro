# Цели: проверка канала (KRO) — Crypto Academy Pro

**Сайт:** https://crypto-academy-pro.onrender.com/  
**Деплой:** ветка `main` → Render (auto-deploy)  
**Обновлено:** 12.06.2026

Документ фиксирует **общие цели продукта** и **конкретные задачи**, над которыми мы работали в сессии по UI проверки гуру.

---

## 1. Главная идея продукта (не менять)

Люди платят не за «отчёт с цифрами», а за **решение** и за то, чтобы не чувствовать себя обманутыми.

| Роль | Описание |
|------|----------|
| **Путник** | Потерял деньги или боится потерять; хочет доказательств и простого ответа «что делать». |
| **Тон** | Умный друг, не юрист. Прямо: «Не плати», «Уйди», «Смотри бесплатно» — без канцелярита. |

Подробнее: [`СТРАТЕГИЯ_ИНСТРУМЕНТ_1.md`](../../СТРАТЕГИЯ_ИНСТРУМЕНТ_1.md)

---

## 2. Приоритет данных при проверке канала

1. **Сначала — текст ленты**, который пользователь вставил (@username / ссылка): Telethon + при необходимости `t.me/s`, в бюджете до ~7 мин (`KRO_ANALYZE_CHANNEL_SYNC_MS`).
2. **Вывод и риск** строятся из прочитанного текста, когда он есть.
3. **Без ленты** — честный fallback по базе/жалобам (`dataset_evidence`), без выдуманных «цитат из постов».
4. Упрощённый режим «только таблицы + сайты» — **только** если явно задано `KRO_HOME_ANALYZE_MODE=quick_sheets_only`.

---

## 3. Цели главного экрана результата (5 секунд — всё ясно)

| # | Элемент | Цель |
|---|---------|------|
| 1 | Бейдж 🔴/🟡/🟢 | Согласован с **вердиктом Mistral** (`person_behind.verdict`), а не только с числом `risk_index`. Слова «Не плати», «Уйди», «Опасно» → 🔴 высокий риск. |
| 2 | Вердикт | Первое слово = решение. Из `person_behind.verdict`. |
| 3 | Раскрытие | `reveal_moment` — скрытая механика канала. |
| 4 | Что делать | `next_action` — конкретное действие. |
| 5 | Буллеты | До 3 фактов с доказательствами. |
| 6 | Кто за каналом | Сетка полей; **пустые** («—», «не упоминается», «аноним») **не показывать**. |

Всё детальное — под кнопкой **«Подробнее — сигналы, цитаты, доказательства»**.

## 4. Цели блока «Подробнее»

### 4.1. Красные флаги / схемы

- Парсить `person_behind.red_flags` (строка или массив) и `flags` из API.
- Показывать **карточки манипулятивных схем** с:
  - названием схемы;
  - коротким «как это работает»;
  - trap-цепочкой (пост → мысль → результат);
  - цитатой из канала.
- Если схем нет — зелёная карточка «Схем не найдено».
- Блок **«Что здесь честно»** — позитивные признаки (убытки в ленте, правила риска, «жалоб нет» и т.п.).

Справочник схем: [`docs/kro-schemes/СХЕМЫ_КРИПТО_СКАМА_TELEGRAM.md`](../kro-schemes/СХЕМЫ_КРИПТО_СКАМА_TELEGRAM.md)

### 4.2. Таблица «Находки» + кнопка «Подробнее»

Пользователь нажимает **«Подробнее»** в строке таблицы (Важность / Суть / Цитата из поста).

**Цели модального окна («SMS-ка»):**

| Требование | Статус |
|------------|--------|
| Открывается **по центру экрана**, перед глазами, с затемнением фона | ✅ |
| Палитра сайта: **фиолет + золото** (`--kro-violet`, `--kro-accent`) | ✅ |
| Цитата поста в «пузыре» как сообщение | ✅ |
| Кнопка-ссылка **«Открыть пост / ленту в Telegram»** | ✅ |
| Блок **«Почему это важно»** + пояснение из отчёта | ✅ |
| Закрытие: крестик, клик по фону, Escape | ✅ |

**Технически:** модалка переносится в `body` (чтобы `position: fixed` не ломался из-за `transform` у родителей). Ссылки на посты подтягиваются из `live_evidence.sample_posts_dated[].url` после новой проверки канала.

## 5. Согласованность риска (главная боль)

**Проблема:** `risk_index` 3/10, а вердикт Mistral — «Не плати, уйди».

**Цель:** пользователь видит **одну правду**:
- бейдж и hero-вердикт согласованы;
- числовой скор остаётся видимым, но **решение** (🔴/🟡/🟢) берётся из слов вердикта, когда там явный сигнал опасности или безопасности.

## 7. Деплой и GitHub

1. Рабочие изменения вливаются в **`main`**.
2. После каждой задачи: `git add` → `git commit -m "..."` → `git push origin main`.
3. Render подхватывает деплой автоматически.
4. Проверка на проде: жёсткое обновление **Ctrl+Shift+R**, тест канала (например `@RichCryptoSignals`, `@daytrader_signals`).

**Не обязательно** мержить черновые PR в GitHub, если код уже в `main` — кнопка Merge может давать ошибку «lock file» и на сайт не влияет.
