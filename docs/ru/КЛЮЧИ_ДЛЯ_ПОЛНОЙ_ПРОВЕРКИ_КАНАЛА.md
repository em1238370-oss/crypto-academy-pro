# Какие ключи нужны, чтобы проверка канала была полной

Чтобы в карточке были **настоящие риски**, **причины из постов канала** (а не «—»), **потери по жалобам**, **вердикт** и **данные по ботам** — нужны перечисленные ниже ключи и один раз вход в Telegram.

---

## Что откуда берётся

| Что в карточке | Откуда берётся | Что нужно для работы |
|----------------|----------------|----------------------|
| **Риск (0–100)** | Анализ **реальных постов** канала через Telegram API (доля постов с рекламой: VIP, сигналы, крипта) | Telegram ключи + сессия (вход один раз) |
| **Причины** | Из **текстов постов**: сколько рекламных постов в неделю, доля ботов в комментариях, цена VIP из постов | То же |
| **Потери** | Лист «Отчёты» в Google-таблице (жалобы с формы «Сообщить о разводе») | Google таблица + сервисный аккаунт |
| **Вердикт** | Считается из риска: высокий / серая зона / низкий | Telegram (риск) или база scam_base |
| **Боты** | Анализ **комментариев под постами** канала через Telegram API (короткие/дубликаты = ботоподобные) | Telegram ключи + сессия |

Без ключей и входа в Telegram система может показать только то, что есть в базе (scam_base) и по жалобам из таблицы. **Настоящие риски и причины из канала** считаются только когда работает живая проверка по Telegram.

---

## 1. Ключи Telegram (обязательно для риска, причин и ботов)

Нужны для того, чтобы **читать посты и комментарии канала** и считать по ним риск, причины и ботов.

| Ключ | Где взять | Куда прописать |
|------|-----------|----------------|
| **TELEGRAM_API_ID** | https://my.telegram.org → API development tools → создать приложение → скопировать **API ID** (число) | В Render: Environment. Локально: в `.env` в корне проекта или в `backend/kro-worker/env` |
| **TELEGRAM_API_HASH** | Там же → **API Hash** (строка) | Туда же |

Без этих двух переменных скрипт проверки по Telegram не запускается — риска, причин из постов и ботов не будет.

---

## 2. Сессия Telegram (вход один раз)

Даже с API ID и Hash скрипт не может читать каналы, пока **аккаунт не «залогинен»**. Один раз нужно войти в Telegram с этого сервера/компьютера — создаётся файл сессии, дальше он используется автоматически.

| Что сделать | Команда / где |
|-------------|----------------|
| Войти в Telegram один раз | В терминале из **корня проекта**: `node scripts/kro-login.js` (или из `backend/kro-worker`: `python3 login_telegram.py`) |
| Результат | В папке `backend/kro-worker/` появляется файл **`kro_worker.session`** (или имя из `TELEGRAM_SESSION_NAME`). Его **не коммитить** в git. |

Если этого файла нет — в ответе будет подсказка «Сначала один раз войдите в Telegram…» и карточка без риска/причин/ботов.

**На Render:** интерактивный вход (код из Telegram в консоль) обычно невозможен. Варианты: один раз сгенерировать сессию **у себя на компьютере**, положить `kro_worker.session` в `backend/kro-worker/` и выложить через секрет/артефакт (сложно), либо запускать живую проверку **на своём ПК или VPS** (воркер), а на Render только база и очередь.

---

## 3. Google Таблица (для потерь, базы, очереди)

Для **потерь по жалобам**, базы каналов (scam_base) и очереди проверки.

| Ключ / что | Описание | Где взять |
|------------|----------|-----------|
| **KRO_SHEET_ID** | ID таблицы из URL: `https://docs.google.com/spreadsheets/d/<этот_id>/edit` | Скопировать из ссылки на твою таблицу |
| **KRO_GOOGLE_CREDENTIALS_JSON** | JSON ключа **сервисного аккаунта** Google (целиком, одной строкой, без переносов) | Google Cloud Console → APIs & Services → Credentials → Create Credentials → Service account → создать ключ JSON. В таблице: Поделиться → добавить email из JSON (`client_email`) с правом **Редактор** |
| **KRO_SCAM_BASE_RANGE** | Лист базы каналов, например `scam_base!A2:H` | Имя листа в твоей таблице |
| **KRO_CHECK_QUEUE_RANGE** | Лист очереди для воркера, например `check_queue!A2:B` | Если используешь воркер |

Без `KRO_SHEET_ID` и `KRO_GOOGLE_CREDENTIALS_JSON` потери из жалоб и запись в базу не работают.

---

## 4. Переменные на Render (сводка)

В Render → твой сервис → **Environment** добавь:

| Переменная | Пример значения |
|------------|-----------------|
| `KRO_SHEET_ID` | `1C1NQwqmLRg59xgplnz5PeghRxaR_YY2lfSWZAJae6qM` |
| `KRO_GOOGLE_CREDENTIALS_JSON` | `{"type":"service_account",...}` (весь JSON одной строкой) |
| `KRO_SCAM_BASE_RANGE` | `scam_base!A2:H` |
| `KRO_CHECK_QUEUE_RANGE` | `check_queue!A2:B` (если есть воркер) |
| **TELEGRAM_API_ID** | число, с my.telegram.org |
| **TELEGRAM_API_HASH** | строка, с my.telegram.org |

После этого на Render будет работать: база, жалобы, потери из таблицы, превью с t.me. **Живая проверка по Telegram** (риск, причины из постов, боты) на Render заработает только если туда как-то передать готовый файл сессии (см. выше).

---

## 5. Локально: полная проверка с риском и ботами

Чтобы **у себя** при нажатии «Проверить» сразу получать риски, причины из канала и ботов:

1. В корне проекта в `.env` (или в `backend/kro-worker/env`) пропиши:  
   `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`, `KRO_SHEET_ID`, `KRO_GOOGLE_CREDENTIALS_JSON`, `KRO_SCAM_BASE_RANGE`.
2. Один раз выполни: `node scripts/kro-login.js` (или `python3 backend/kro-worker/login_telegram.py`) и войди в Telegram (номер + код из приложения).
3. Убедись, что в `backend/kro-worker/` появился файл `kro_worker.session`.
4. Запусти бэкенд (например `node backend/server.js`) и открой сайт локально. При проверке канала бэкенд вызовет `check_once.py`, тот прочитает посты и комментарии канала и вернёт реальные риск, причины, VIP, ботов, вердикт. Потери подтянутся из таблицы по жалобам.

---

## Кратко: почему было пусто и что нужно

- **Пустые риски/причины/боты** — потому что не было либо Telegram ключей, либо сессии (входа в Telegram), либо бэкенд не смог запустить Python/Telethon.
- Чтобы **не из воздуха**, а **из канала**: нужны **TELEGRAM_API_ID**, **TELEGRAM_API_HASH** и **один раз вход** (`node scripts/kro-login.js`), чтобы появился `kro_worker.session`.
- **Потери** — из Google-таблицы (лист отчётов), для этого нужны **KRO_SHEET_ID** и **KRO_GOOGLE_CREDENTIALS_JSON** и доступ таблицы для сервисного аккаунта.
- **Вердикт** — считается из риска (если есть живая проверка) или берётся из строки в scam_base.

Все ключи и шаги выше — то, что нужно, чтобы карточка заполнялась настоящими рисками, причинами из постов, потерями и вердиктом, а по ботам было «N%» из комментариев канала, а не «нет данных».
