# Факторы цифр на главной (живой счётчик Фишки 1)

Откуда берутся метрики «новых скам-каналов за день», «Потеряно ₽», «Telegram каналов», «Курсы фейк-продуктов», «Топ-3 сегодня» и блок «За последние 24 часа» (жертвы/гарантия).

---

## Когда что показывается

- **Если Google Таблица настроена и на листе «Отчёты» есть данные** — приоритет у таблицы. API `GET /api/kro/live-counter` считает по листу (дата, канал, сумма, тип, статус) и отдаёт ваши реальные цифры. Подпись: «Данные из вашей таблицы (отчёты и жалобы).»
- **Если таблица пуста или недоступна** — API отдаёт данные из файла `backend/data/kro-reference-stats.json`. Этот файл обновляется скриптом `backend/kro-worker/fetch_live_stats.py` (парсинг vklader, tgrev, опционально Telegram). Подпись: «Данные из интернета: vklader, tgrev. Обновлено …»

---

## Метрика → источник → как считается

| Метрика | Источник 1 (приоритет) | Источник 2 (fallback) | Как считается |
|--------|-------------------------|------------------------|----------------|
| **Новых скам-каналов за день** | Лист «Отчёты»: число строк с датой «сегодня» | Парсер: разница «вчера/сегодня» по числу каналов (prevChannelCount в JSON) или число постов за 24ч в каналах жалоб | В парсере хранятся `prevChannelCount` и `prevDate` в том же JSON; при смене даты `channelsToday = max(0, current - prev)`. |
| **Потеряно ₽** | Лист «Отчёты»: сумма по колонке «сумма ₽» | Парсер: суммы из текстов Telegram и при возможности vklader/tgrev; если нет — оценочная константа из отчётов (в подписи указано «оценка»). | Регулярки в `fetch_live_stats.py` извлекают суммы из сообщений. |
| **Telegram каналов** | Лист «Отчёты»: число строк с типом TG | Парсер: уникальные @/t.me с vklader + tgrev + Telegram | Уже считается в `fetch_live_stats.py`. |
| **Курсы фейк-продуктов** | Лист «Отчёты»: число строк, где тип содержит «курс»/«фейк»/course | Парсер: подсчёт слов «курс», «марафон», «vip» на страницах vklader/tgrev | В скрипте парсинга. |
| **Топ-3 сегодня** | Лист «Отчёты»: 3 строки за сегодня с макс. суммой (канал, сумма, статус) | Парсер: из извлечённых пар (канал, сумма) из Telegram и веба — топ-3 по сумме; при отсутствии сумм — топ-3 каналов со статусом «Из парсинга» | В `fetch_live_stats.py` функция `_build_top3`, результат пишется в `kro-reference-stats.json`. |
| **«За 24 часа»: люди/жертвы** | Лист «Отчёты»: количество строк за сегодня (жалоб за 24ч) | Парсер: число постов за 24ч в каналах из `KRO_SOURCE_CHANNELS` (оценка активности жалоб) | Поле `victims24h` в API; на главной подставляется в текст «N человек купили «гарантию прибыли»». |

---

## Что нужно для работы

- **Таблица:** `KRO_SHEET_ID`, `KRO_GOOGLE_CREDENTIALS_JSON` (или `GOOGLE_APPLICATION_CREDENTIALS`) — тогда счётчик и Топ-3 считаются из листа «Отчёты».
- **Парсер (реальные числа из интернета):** запуск `fetch_live_stats.py` по расписанию:
  - **Локально:** cron раз в сутки, например `0 6 * * * cd /path/to/backend/kro-worker && python3 fetch_live_stats.py`. Результат пишется в `backend/data/kro-reference-stats.json`.
  - **Render:** Cron Job раз в сутки может вызывать скрипт; результат нужно сохранять (например скрипт отправляет `POST /api/kro/ingest-parsed` на ваш бэкенд, который записывает JSON в память или на persistent disk; либо обновлённый `kro-reference-stats.json` коммитится в репозиторий через GitHub Actions).
  - **Опционально для парсера:** `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`, `KRO_SOURCE_CHANNELS` — тогда скрипт дополнительно читает каналы жалоб/сигналов в Telegram и считает посты за 24ч, суммы и топ-3 из сообщений.

Подробнее про запуск парсера: [КАК_ЗАПУСТИТЬ_ПАРСЕР.md](../../backend/kro-worker/КАК_ЗАПУСТИТЬ_ПАРСЕР.md) (в `backend/kro-worker/`) и [ПЛАН_ПАРСИНГ_ОТКРЫТЫХ_ИСТОЧНИКОВ.md](ПЛАН_ПАРСИНГ_ОТКРЫТЫХ_ИСТОЧНИКОВ.md).
