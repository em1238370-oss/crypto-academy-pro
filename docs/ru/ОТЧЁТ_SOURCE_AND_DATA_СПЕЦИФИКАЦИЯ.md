# СПЕЦИФИКАЦИЯ ОТЧЁТА `SOURCE & DATA`
(ОДИН GOOGLE DOC, БЕЗ ТАБЛИЦ отдельно)

**Компактный формат публикуемого отчёта за цикл** (шапка, живой лог только события, таблицы риска и жалоб, итоги с JSON, чек‑лист) описан в [СТРУКТУРА_ОТЧЁТА_ЦИКЛ_7_БЛОКОВ.md](СТРУКТУРА_ОТЧЁТА_ЦИКЛ_7_БЛОКОВ.md).

Документ заполняется **каждые 12 часов** для нового цикла мониторинга.  
Одна страница = один 12‑часовой цикл.

---

## 1. ЗАГОЛОВОК ЦИКЛА

В самом верху документа (жирно, крупно):

**СКАМ‑МОНИТОРИНГ КРИПТО — SOURCE & DATA**  
**Период цикла:** с `DD.MM.YYYY HH:MM` по `DD.MM.YYYY HH:MM` (MSK)  
**Время старта поиска:** `HH:MM` (MSK)  
**Время окончания поиска:** `HH:MM` (MSK)  
**Время формирования отчёта:** `HH:MM–HH:MM` (MSK)

Пример:

**СКАМ‑МОНИТОРИНГ КРИПТО — SOURCE & DATA**  
**Период цикла:** с 02.03.2026 00:00 по 02.03.2026 12:00 (MSK)  
**Время старта поиска:** 11:00 (MSK)  
**Время окончания поиска:** 11:30 (MSK)  
**Время формирования отчёта:** 11:30–11:59 (MSK)

## 2. БЛОК 1 — МЕТАДАННЫЕ СБОРА

Этот блок всегда идёт сразу после заголовка.  
Задача — зафиксировать рамки и ИСТОЧНИКИ ЦИКЛА.

### 2.1. Источники в этом цикле

Список **строго с активными ссылками**, каждый пункт с временем начала обращения:

1. **TGStat**  
   - Время начала обращения: `HH:MM`  
   - Использованный поисковый запрос (точно, текстом):  
     _например:_ `"криптовалюта" + сортировка по новизне`  
   - Ссылка на результат запроса (URL):  
     _например:_ `https://tgstat.ru/search?query=криптовалюта&sort=date`

2. **Telega**  
   - Время начала обращения: `HH:MM`  
   - Раздел/фильтр (точно, текстом):  
     _например:_ `категория "cryptocurrencies", сортировка по новизне`  
   - Ссылка на страницу каталога:  
     _например:_ `https://telega.in/catalog?category=cryptocurrencies`

3. **Чаты с жалобами**  
   - Время начала просмотра: `HH:MM`  
   - Перечень чатов (название + ссылка):  
     - `"Скам крипта"` — `https://t.me/xxxxx`  
     - `"Крипта — мошенники"` — `https://t.me/yyyyy`  

Все эти строки **обязательны**.  
Если какой‑то источник в этом цикле НЕ использовался — это явно пишется:

- **TGStat:** не использовался в этом цикле (причина: …).  
(Но в нормальной работе ожидается, что используются все три.)

## 3. БЛОК 2 — СЫРОЙ ПОИСК ПО ИСТОЧНИКАМ

Задача блока — **полностью записать весь процесс поиска**, шаг за шагом, по каждому источнику ОТДЕЛЬНО.  
Каждый источник — отдельный подзаголовок.

### 3.1. TGStat — СЫРОЙ ПОИСК

Подзаголовок (подчёркнутый):

**TGStat — сырые результаты поиска**

Далее — последовательные строки, одна строка = один найденный канал.  
Порядок: **ровно в том виде, как ты их проходишь** (чтобы путь можно было восстановить).

Формат записи одного канала (строка, можно через тире или список):

- Время фиксации: `HH:MM`  
- Канал: `@username`  
- Ссылка: `полный URL на TGStat`  
- Дата создания канала (как указано в источнике)  
- Количество подписчиков на момент фиксации  
- Рост за последние 24 часа (если есть в источнике)  
- Наличие / отсутствие VIP / платных услуг (сумма, если есть)  

Пример:

11:08 — канал `@TONVIPnew`  
-  Ссылка: `https://tgstat.ru/channel/tonvipnew`  
-  Дата создания: 28.02.2026  
-  Подписчики: 3 400  
-  Рост за 24 часа: +1 200  
-  VIP/платные услуги: есть, тариф 7 900₽

Все такие строки подряд. **Ничего не скрывать**, даже если канал потом не пройдёт фильтр.

---

### 3.2. Telega — СЫРОЙ ПОИСК

Подзаголовок:

**Telega — сырые результаты поиска**

Формат записи аналогичный:

- Время фиксации: `HH:MM`  
- Канал: `@username`  
- Ссылка: полный URL на Telega  
- Дата добавления в каталог  
- Категория / тема (криптовалюта и т.п.)  
- Наличие / тип рекламы / VIP (если есть цены — указать)  

Пример:

11:15 — канал `@SignalProX`  
-  Ссылка: `https://telega.in/channel/signalprox`  
-  Дата добавления: 01.03.2026  
-  Категория: cryptocurrencies  
-  VIP/реклама: есть, от 5 500₽ за размещение

---

### 3.3. Чаты — СЫРЫЕ ЖАЛОБЫ

Подзаголовок:

**Чаты — сырые жалобы (ВСЕ сообщения за период)**

Каждая жалоба фиксируется отдельно, даже если она потом будет отсеяна.  
Формат:

- Время сообщения в чате: `HH:MM`  
- Чат: `"название"`  
- Пользователь: `@user` (можно частично)  
- Ссылка на сообщение или краткое описание скрина  
- Канал/сайт, на который жалуются (если указан)  
- Указанная сумма (если есть, обязательно с ₽ или иной валютой)  
- Доп. комментарий, если важно (например, "без суммы", "старше периода")

Пример:

11:22 — чат `"Скам крипта"`  
-  Пользователь: `@lost_money123`  
-  Ссылка на сообщение: `https://t.me/xxxxx/12345`  
-  Жалоба на: `@MoonPumpVIP`  
-  Указанная сумма: 50 000₽  
-  Комментарий: написал, что его заблокировали после перевода

## 4. БЛОК 3 — ПРИМЕНЕНИЕ ФИЛЬТРОВ (ПОШАГОВО)

Задача — показать, **как система отсеяла лишнее** и почему.

Подзаголовок:

**Применение фильтров к найденным каналам**

### 4.1. Фильтр по каналам (возраст, VIP, рост)

Для каждого канала из сырых данных TGStat/Telega:

Формат:

- Канал: `@username`  
- Источник: `TGStat` / `Telega`  
- Решение: **ПРОШЁЛ ФИЛЬТР** / **ОТКЛОНЁН**  
- Причины (по пунктам)  

Примеры:

Канал: `@TONVIPnew`  
Источник: TGStat  
Решение: **ПРОШЁЛ ФИЛЬТР**  
Причины:  
1) Возраст канала < 7 дней (создан 28.02.2026).  
2) Есть VIP/платные услуги (7 900₽).  
3) Рост подписчиков за 24ч > 1 000 (факт: +1 200).

Канал: `@OldCryptoSignal`  
Источник: TGStat  
Решение: **ОТКЛОНЁН**  
Причина: возраст 45 дней (лимит: 7 дней).

---

### 4.2. Фильтр по жалобам

Подзаголовок:

**Применение фильтров к жалобам**

Для каждой жалобы из блока "сырые жалобы":

- Жалоба на канал: `@username` (или сайт)  
- ID/ссылка на сообщение: `…`  
- Решение: **УЧТЕНО В РАСЧЁТЕ** / **НЕ УЧТЕНО**  
- Причины:

Пример (учтено):

Жалоба на канал: `@MoonPumpVIP`  
Сообщение: `https://t.me/xxxxx/12345`  
Решение: **УЧТЕНО В РАСЧЁТЕ**  
Причины:  
1) Указана сумма (50 000₽).  
2) Период сообщения попадает в текущий цикл.  
3) Это жалоба от нового пользователя (нет дубликата по этому юзеру и сумме).

Пример (не учтено):

Жалоба на канал: `@SomeChannel`  
Сообщение: `https://t.me/yyyyy/67890`  
Решение: **НЕ УЧТЕНО**  
Причины:  
1) Сумма не указана (только текст "меня обманули").  
2) Сообщение старше 12 часов.

## 5. БЛОК 4 — РАСЧЁТ СУММ И ТОП‑3

Здесь должен быть **прозрачный расчёт**, как из отфильтрованных жалоб получились цифры.

### 5.1. Сводка по жалобам по каналам

Подзаголовок:

**Сводка по жалобам (по каналам)**

Для каждого канала, у которого есть УЧТЁННЫЕ жалобы:

- Канал: `@username`  
- Список сумм жалоб: `50 000₽ + 27 000₽ + 40 000₽ + 30 000₽`  
- Итого по каналу: `147 000₽`  

В конце — общая сумма:

**Общая сумма потерь за период:**  
147 000₽ (MoonPumpVIP) + 98 000₽ (crypto-fast.pro) + … = **292 000₽**

### 5.2. Формирование ТОП‑3

Подзаголовок:

**Формирование ТОП‑3 рисковых объектов**

Шаги:

1. Список всех каналов/сайтов с суммами потерь и количеством жалоб.  
2. Описание правила сортировки (важно прописать):  
   - Сначала по сумме потерь (по убыванию).  
   - При равенстве — по количеству жалоб (по убыванию).  
   - При полном равенстве — по новизне (более новый выше).  
3. Итоговый список ТОП‑3 с пояснением по каждому:

Пример:

1) `@MoonPumpVIP` — 147 000₽, 4 жалобы.  
2) `crypto-fast.pro` — 98 000₽, 3 жалобы.  
3) `@TONVIPnew` — 0₽ (жалоб нет, но канал новый и прошёл фильтр риска).

Если кто‑то исключён по правилу "был в Топ‑3 вчера" — это тоже пишем:

Канал `@ScamRepeat` НЕ добавлен в ТОП‑3,  
причина: уже был в Топ‑3 в предыдущем цикле (анти‑дублирование).

## 6. БЛОК 5 — СВЯЗКА С ИТОГОВЫМИ ЦИФРАМИ ДЛЯ САЙТА

В самом конце — небольшой блок, который связывает Source & Data с кратким отчётом/JSON (для сайта):

**Итоговые значения для публикации:**

- Суммарные потери за период: `YYY 000₽`  
  (взято из блока "Сводка по жалобам").  
- Количество учтённых жалоб: `N`.  
- Список ТОП‑3:  
  1) `…`  
  2) `…`  
  3) `…`

**Как эти значения попадают на сайт:** см. [БЛОК_5_ДЛЯ_ПУБЛИКАЦИИ.md](БЛОК_5_ДЛЯ_ПУБЛИКАЦИИ.md).

## 7. ВАЖНЫЕ ПРАВИЛА ДЛЯ РЕАЛИЗАЦИИ

1. **Всё делается в ОДНОМ Google Doc.**  
   Никаких отдельных файлов, таблиц — всё внутри этого документа.

2. **Никаких скрытых шагов.**  
   Каждый найденный канал и каждая жалоба сначала записываются в "сырые" блоки.  
   Любое решение (учтён/не учтён, прошёл/не прошёл) должно иметь пояснение "почему".

3. Разрешено и приветствуется:  
   - жирный шрифт для важных заголовков;  
   - подчеркивание блоков "сырые данные", "фильтры", "расчёт";  
   - абзацы, отступы, нумерованные/маркированные списки — для удобства чтения человеком.

4. Документ должен быть написан так, чтобы человек,  
   который видит его **впервые**, за 10–15 минут мог понять:
   - откуда взяты цифры,  
   - какой канал откуда появился,  
   - почему он попал или не попал в итог.
