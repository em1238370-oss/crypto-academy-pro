# ЧАСТЬ II. СПЕЦИФИКАЦИЯ ФОРМАТА ОТЧЁТА «СКАМ‑МОНИТОРИНГ» (ТЗ)

Требования к структуре отчёта за день, формату временной линии, главной таблице «Объекты и риск» и правилам заполнения ячеек.

---

## ТЗ.1. Структура документа по дню

1. Для **каждого дня** создаётся один лог‑блок:
   - `Период: DD.MM.YYYY 00:00 – DD.MM.YYYY 23:55 (MSK)`
   - `Время формирования: DD месяц, 23:55 MSK`

2. Ниже идёт раздел:
   - `Временная линия дня:`
   - и строки событий по времени.

3. Внутри одного дня:
   - время идёт по возрастанию от 00:00 до 23:55;
   - **каждая отметка времени (HH:MM) используется не больше ОДНОГО раза**;
   - запрещено копировать один и тот же блок событий (например, 03:00 с теми же каналами) многократно.

4. Списки каналов **не пишутся** в лог по времени. Все каналы и детали по ним фиксируются только в таблице.

#### Правила по времени (обязательно)

1. Для каждого дня в документе используется только один диапазон:
   - `Период: DD.MM.YYYY 00:00 – DD.MM.YYYY 23:55 (MSK)`
   - `Время формирования: DD месяц, 23:55 MSK`
2. Внутри «Временной линии дня» время **всегда идёт по порядку**, от 00:00 до 23:55.
3. **Каждое значение HH:MM можно использовать только один раз за день.**
   - Если уже записана строка на 03:00, в этот день второй строки «03:00 — …» быть не должно.
4. Пример правильной последовательности (00:00, 00:05, 00:10, 00:20, 00:30):
   - `00:00 — Начат сбор данных за период 00:00–23:55.`
   - `00:05 — TGStat/Telega: найдено каналов по фильтрам — TGStat 0, Telega 0.`
   - `00:10 — За последние 10 минут новых объектов по фильтрам не найдено, источники доступны.`
   - `00:20 — TGStat/Telega: найдено 12 новых сигнал‑каналов, добавлены в таблицу «Объекты и риск».`
   - `00:30 — За последние 10 минут новых объектов по фильтрам не найдено, источники доступны.`
5. В лог по времени запрещено вставлять длинные списки каналов. Лог фиксирует только:
   - сколько найдено объектов,
   - где искал,
   - были ли ошибки/недоступные источники.

## ТЗ.2. Формат временной линии

Формат одной строки лога:

`HH:MM — краткое описание события (ОДНА строка)`

Пример:

```
Период: 07.03.2026 00:00 – 07.03.2026 23:55 (MSK)
Время формирования: 7 марта, 23:55 MSK

Временная линия дня:
00:00 — Начат сбор данных за период 00:00–23:55.
00:05 — TGStat/Telega: найдено каналов по фильтрам — TGStat 0, Telega 0.
00:10 — За последние 30 минут новых объектов по фильтрам не найдено, источники доступны.
00:20 — TGStat/Telega: найдено каналов по фильтрам — TGStat 0, Telega 53.
…
23:55 — Завершён сбор данных за день, таблицы обновлены.
```

Правила:
- лог отвечает только на «когда» и «что в общем произошло» (нашли/не нашли, сколько, был ли перерасчёт);
- **никаких списков @каналов и «(3/6 рисков)» в логах**.

## ТЗ.3. Маршрут поиска (где и как искать)

Порядок действий при поиске каналов и жалоб.

#### Шаг 1. Поиск каналов (Telegram)

1. В каталогах Telegram и в глобальном поиске Telegram ищи каналы по ключевым словам:
   - `crypto signals`, `крипто сигналы`, `VIP signals`, `pump`, `x2`, `x5`, `profit`, `заработок`, `доход`, `без риска`.
2. Отбирай только те каналы, которые:
   - связаны с криптой/трейдингом,
   - дают сигналы или обещают доход,
   - продают VIP, курсы, платные подписки.
3. Каналы, которые просто дают новости/аналитику без продажи сигналов и дохода, отмечай как:
   - `крипто‑канал (новости)` и статус `без риска (новости/аналитика)`
   или вообще не включай в таблицу риска.

#### Шаг 2. Поиск жалоб в Telegram

1. Используй чаты, посвящённые скаму и жалобам (которые уже заданы в настройках), и ищи там:
   - по названию/юзернейму канала (`@username`),
   - по словам «скам», «обманули», «развод», «слил депозит», «мошенники».
2. Фиксируй:
   - сколько разных людей жалуются (по никам),
   - какие формулировки они используют («после оплаты VIP заблокировали», «слил депозит по их сигналам»).
3. В таблицу в столбец «Жалобы / отзывы» пиши короткое резюме:
   - «2 человека в чате X пишут, что после сигналов канала слили депозит (без суммы).»
   - «В чате Y жалуются, что после оплаты VIP автор перестаёт отвечать.»

#### Шаг 3. Поиск отзывов в интернете

Для каждого найденного канала/сайта:

**Примеры запросов:** `«имя канала» + отзывы` / `«имя канала» + scam` / `«имя канала» + обман` / `«имя канала» + развод` / `«имя канала» + жалобы`.

**Где искать:** форумы по трейдингу/крипте, комментарии под статьями, посты в соцсетях, где обсуждают этот канал/бот/сайт.

В таблицу заноси только то, что реально нашли. Если ничего не нашли — писать: «Жалоб в открытых источниках не найдено (поиск по Telegram и интернету).»

## ТЗ.4. Главная таблица «Объекты и риск»

Одна таблица на день; создаётся вставкой таблицы (не текстом). В столбце «Объект / ссылка» ссылки должны быть кликабельными (переход в канал Telegram для проверки).

### ТЗ.4.1. Столбцы (8 штук) — описание

Вставьте таблицу (Вставка → Таблица): 3 столбца, 9 строк (1 строка — заголовки). Заголовки: №, Столбец, Кратко: что писать.

Строки 2–9:
1. Объект / ссылка — @username + гиперссылка t.me; или example.com + ссылка; не про крипту/сигналы — не включать
2. Тип — Одно значение: сигнал‑канал, крипто‑канал (новости), бот, сайт/курс, обучение
3. Источник — каталог Telegram, поиск в Telegram, чат с жалобами, поиск в интернете; до двух через «+»
4. Краткое описание — 1–2 предложения по факту, без оценок «мошенники»
5. VIP / деньги — Реальные данные: цена VIP, «не указана», «не обнаружено»
6. Жалобы / отзывы — По факту: кто пишет, суммы если есть; «жалоб не найдено» если нет
7. Признаки риска (флаги) — Конкретные флаги по факту (структура/поведение + VWAP при использовании)
8. Итоговый статус — Резюме по 4–7: в риске / поведенческий риск / без риска / под наблюдением

В отчёте за день: первая строка таблицы — заголовки (жирным); далее по одной строке на каждый объект.

### ТЗ.4.2. Правила заполнения ячеек строки

Каждая строка (N ≥ 2) соответствует одному объекту (канал, бот или сайт).

**Столбец 1 — Объект / ссылка**
- Для канала: текст `@username` и гиперссылка `https://t.me/username` на этот же текст.
- Для сайта/курса: текст `example.com` и ссылка `https://example.com`.
- Если ссылка не открывается или объект не про крипту/сигналы — строку вообще не создавать.

**Столбец 2 — Тип**

Одно короткое значение, например: `сигнал‑канал`, `крипто‑канал (новости)`, `бот`, `сайт/курс`, `обучение`. Никаких описаний здесь, только тип.

**Столбец 3 — Источник**

Откуда взяли объект: `каталог Telegram`, `поиск в Telegram`, `чат с жалобами`, `поиск в интернете`. Допускается до двух источников через «+» (например, `каталог + жалобы`).

**Столбец 4 — Краткое описание**

1–2 предложения по факту, что делает объект. Примеры: «Канал даёт торговые сигналы по криптовалютам и обещает высокий процент успешных сделок.» / «Публикует новости рынка без продажи сигналов или VIP.» Только то, что реально видно в описании и постах. Без оценок «мошенники», «плохой».

**Столбец 5 — VIP / деньги**

Как объект зарабатывает. Примеры: «VIP‑подписка 15 000₽ / месяц»; «Есть закрытый VIP‑канал, цена не указана, просит писать в личку»; «Платных услуг не обнаружено.» Только реальные данные. Никаких выдуманных цен.

**Столбец 6 — Жалобы / отзывы**

Итог по жалобам. Примеры: «2 человека в чате X пишут, что после сигналов слили депозит (без суммы).» / «На форуме Y есть отзывы, что после оплаты VIP автор перестал отвечать.» / «Жалоб за период не найдено (поиск по чатам и интернету).» Если сумм нет — не придумывать. Если жалоб нет — честно писать, что не найдено.

**Столбец 7 — Признаки риска (флаги)**

Список конкретных флагов, каждый опирается на факт.

Структура/поведение:
- «новый канал (< 14 дней)»
- «есть дорогой VIP (от ~10 000₽)»
- «обещания x2/x5, „без риска“, „гарантированный доход“»
- «много картинок монет со стрелками вверх/вниз»
- «объяснения по монетам короткие, без сценариев риска»
- «активно продаёт VIP („пиши в ЛС“, „осталось мало мест“)»
- «показывает только прибыльные сделки, убытки не показывает»

Дополнительно, если используется VWAP‑анализ сигналов:
- «часто даёт лонги ниже VWAP (торговля против VWAP)»
- «часто даёт шорты выше VWAP»
- «сигналы сильно далеко от VWAP (>2–3% смещения)»

Флаги можно писать через запятую или с новой строки внутри ячейки. Ни одного флага нельзя придумать — только по реальному контенту/жалобам/сигналам.

**Столбец 8 — Итоговый статус**

Краткий вывод, основанный на столбцах 4–7:
- «в риске (структура + поведение + жалобы)»
- «поведенческий риск (жалоб нет)»
- «жалобы, но мало данных по контенту»
- «без риска (новости/аналитика)»
- «под наблюдением (мало данных)»

Статус никогда не ставится «из головы», только как резюме предыдущих столбцов.

### Для каждого сигнального канала (чек‑лист)

При внесении каждого канала в таблицу необходимо проверить и зафиксировать:

1. **Структура:**
   - новый или старый канал (примерно по дате создания/активности),
   - есть ли VIP/платная подписка, курс, закрытый клуб,
   - есть ли обещания дохода («x2 за день», «без риска», «гарантированная прибыль»).
2. **Поведение:**
   - использует ли картинки монет со стрелками вверх/вниз,
   - даёт ли поверхностные «обоснования» на 3–5 строк без сценариев риска,
   - постоянно ли зовёт в VIP/личку («пиши в ЛС», «успей в VIP»),
   - показывает ли убытки или только прибыльные сделки.
3. **Жалобы:**
   - есть ли реальные жалобы в чатах и интернете,
   - есть ли истории про слив депозита, обман с VIP, блокировку после оплаты,
   - есть ли указанные суммы потерь (если да — фиксируй).

Результаты проверки отражаются в столбцах «Краткое описание», «VIP / деньги», «Жалобы / отзывы», «Признаки риска (флаги)» и «Итоговый статус».

### Честность данных (только из интернета, не из головы)

Допустимые источники выводов и формулировок:

1. Все выводы должны опираться только на:
   - реальные посты и описание канала,
   - реальные сообщения в чатах,
   - реальные страницы и комментарии в интернете.
2. Запрещено:
   - придумывать жалобы и суммы потерь,
   - придумывать признаки риска («мошенники», «кидают»), если это не подтверждается контентом или жалобами,
   - приписывать каналу то, чего нет в его постах.
3. Разрешено и правильно:
   - писать «жалоб не найдено»,
   - писать «цена не указана»,
   - писать «мало данных, объект под наблюдением»,
   если информации действительно мало.

### Пример строки таблицы («как надо»)

- **Признаки риска (флаги):** «новый канал (< 14 дней); есть дорогой VIP; обещания высокого дохода без описания рисков; много картинок монет со стрелками вверх; показывает только прибыльные сделки; есть жалобы на слив депозита и отсутствие связи после оплаты VIP.»
- **Итоговый статус:** «в риске (структура + поведение + жалобы)»

Все описания должны опираться на реально найденные данные. При отсутствии подтверждений указывать «нет данных» или «жалоб не найдено», а не придумывать формулировки.

# Модель канала и скоринг риска

Канал рассматривается не как одна строка в таблице, а как **объект** с признаками и историей.

## 7.1. Модель

Каждый канал — объект с:

- **статическими признаками** (что «вшито» в структуру);
- **динамическими признаками** (как ведёт себя со временем);
- **связями** (с кем перекликается, кого рекламирует);
- **внутренним скорингом риска**, который обновляется каждый день.

Система обязана: собрать набор численных и логических признаков; хранить их историю минимум 14 дней; каждый день пересчитывать скоринг и статус.

## 7.2. Признаки уровня 1 — паспорт (статические)

То, что почти не меняется:

- **Возраст:** дни с первого поста.
- **Язык/регион:** RU / EN / AR и т.д.
- **Тип:** сигналы / сигналы+обучение / памп / арбитраж и т.д.
- **Наличие платных продуктов:** VIP чат (да/нет), курс (да/нет), платный бот (да/нет).
- **Диапазон цен по продуктам:** дешёвый (до N), средний, дорогой (выше N).
- **Формальные обещания:** встречаются ли фразы «гарантируем», «без риска», «x2/x5», «100% профит» и т.п.

Каждый пункт — отдельный флаг или число. Уже на этом уровне формируется базовый «структурный риск».

## 7.3. Признаки уровня 2 — анализ контента

По последним ~100 постам система подсчитывает распределения:

1. **Доля сигнальных постов:** сколько постов — сигналы (вход/выход/уровни), сколько — обучение/аналитика, сколько — прямой маркетинг VIP.
2. **Частота слов про риск:** сколько раз — «риск», «stop», «SL», «может не сработать»; сколько — «точно», «гарантированно», «100%», «без риска». Результат: **индекс честности про риск** и **индекс агрессивной уверенности**.
3. **Баланс плюсов/минусов:** количество постов про успешные сделки vs про неудачные/стоп‑лоссы; **коэффициент однобокости** (50 плюсов и 0 минусов — подозрительно).
4. **Давление VIP:** доля постов с призывом в VIP/личку/закрытый чат; наличие срочности («только сегодня», «последний шанс»).
5. **Длина и качество объяснений:** средняя длина текстов при сигнале; доля сигналов с планом B/C (альтернативные сценарии); доля сигналов «картинка + 2 фразы».

Итог: индексы — прозрачности риска, агрессивного маркетинга, однобокости результатов, пустых объяснений.

## 7.4. Признаки уровня 3 — связи и экосистема

Система смотрит не только на сам канал:

1. **Исходящие связи:** кого канал рекламирует; на какие чаты/боты/каналы ссылается («наш VIP‑чат», «наш бот», «партнёр»).
2. **Входящие связи:** кто рекламирует канал (в т.ч. из уже помеченных как риск).
3. **Похожесть:** похожесть текстов и структуры постов на известные скам‑каналы (шаблоны приветствия, продающих постов, скрипты продаж VIP).

Результат: **экосистемный индекс риска** — канал новый «с нуля» или встроен в известную токсичную сеть.

## 7.5. Признаки уровня 4 — динамика 14 дней

Ведётся **временной ряд по каждому индексу**:

- Каждый день пересчитываются индексы (агрессивность, честность риска, доля VIP‑постов, жалобы и т.д.).
- Сравнение с прошлым днём / прошлой неделей.
- Важно не только «что сейчас», но **стало ли хуже** (рост агрессивности, больше VIP, меньше разговоров о риске) или лучше (канал стал спокойнее, показывает минусы).

Для каждого индекса — не только значение, но и **производная** (рост/падение за 3–7–14 дней).

## 7.6. Итоговый скоринг

Сложный скоринг (не примитивный «3/6 рисков») состоит из:

1. **Структура (паспорт)** — вес ~30%.
2. **Контент (поведение)** — вес ~30–40%.
3. **Связи (экосистема)** — вес ~20%.
4. **Динамика за 14 дней** — вес ~10–20%.

Шкала:

- **0–30:** низкий риск / наблюдение.
- **30–60:** поведенческий риск.
- **60–100:** высокий риск / скам‑зона.

На выходе человек должен видеть **человеческое объяснение**: какие именно признаки увидели, как они менялись за 14 дней, почему канал «в риске» или «под наблюдением» — а не только число.

## 7.7. Блок-инструкция (обязательные правила оценки)

Ты не имеешь права оценивать канал по принципу «есть жалобы / нет жалоб».

Для каждого нового канала ты обязан:

1. Собрать **структурные признаки** (возраст, платные продукты, обещания дохода).
2. Проанализировать **последние ~100 постов** и посчитать: долю сигналов/рекламы/аналитики, индекс честности про риск, баланс плюсов и минусов, силу давления VIP, долю пустых объяснений.
3. Построить **карту связей**: с кем канал связан, на кого похож, с кем он в одной сети.
4. Вести **историю этих показателей минимум 14 дней** и каждый день пересчитывать: стало лучше / хуже, усилились или ослабли признаки скама.

На основе всех этих уровней ты вычисляешь внутренний скоринг риска, но в документе всегда объясняешь человеческим языком: какие именно признаки ты увидел, как они менялись за 14 дней, почему ты решил, что канал «в риске» или «только под наблюдением».

# Приложение

**Обновления каждые 5 мин.** Скрипт `update_live_log_5min.py` каждые 5 минут обновляет счётчики (TGStat, Telega, жалобы) и дописывает строку в блок «Обновления каждые 5 мин» документа SOURCE & DATA. Последняя добавленная строка выделяется жирным. В документе должен присутствовать плейсхолдер «События за период — ниже», который скрипт заменяет на актуальные строки лога.

**Канонический источник методологии:** отчёт «СКАМ‑МОНИТОРИНГ | Source & Data» (PDF / Google Doc). Данные блока «Результаты в цифрах» на сайте должны соответствовать переменным раздела 6 указанного отчёта.
