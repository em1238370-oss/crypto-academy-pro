# Как обновить документ SOURCE & DATA

**На Mac в терминале нужно писать `python3`, а не `python`** — иначе будет ошибка «command not found».

Документ **SOURCE & DATA** в Google Docs обновляется **только при запуске** скрипта. Пока скрипт не запущен — в документе остаются старые данные и пустые таблицы.

**Важно:** нельзя перезаписывать рабочий Google Doc простым текстом из `Sources-and-Data-ВСТАВИТЬ-В-GOOGLE-DOC.txt`. Такой способ удаляет нативные таблицы Google Docs и может сломать живой блок `События за период — ниже`. Для рабочего документа используйте только точечные скрипты: `insert_risk_table_into_sources_doc.py`, `update_sources_doc_once.py`, `fix_sources_doc_block_once.py`.

## Что сделать, чтобы таблицы и текст в документе обновились

1. Открой **Терминал** (на Mac: Программы → Утилиты → Терминал, или поиск «Terminal»).

2. Перейди в папку скрипта (обязательно, иначе будет ошибка «файл не найден»):
   ```bash
   cd /Users/elizavetamedvedeva/Documents/GitHub/crypto-academy-pro/backend/kro-worker
   ```

3. Запусти обновление документа:
   ```bash
   python3 update_sources_doc_once.py
   ```
   Подожди 15–30 секунд, пока скрипт отработает.

4. В выводе в терминале появится ссылка на документ. Открой её в браузере (или открой документ по своей ссылке) и нажми **F5** (обновить страницу).

После этого в документе должны появиться: заголовки таблиц, данные в ячейках (или «(нет данных)» / «Жалоб за этот период не найдено», если данных ещё нет). Если в папке есть файл `../data/kro-12h-stats.json` с данными — они подставятся в таблицы.

**Отправка на сайт:** если в `.env` задан **`KRO_SITE_UPDATE_URL`** (например `https://crypto-academy-pro.onrender.com/api/kro/update`), то после обновления документа те же данные автоматически отправляются на сайт — ячейки (LIVE, потери, Топ-3, ссылка на документ) обновятся на crypto-academy-pro. При необходимости задай также `KRO_SITE_UPDATE_SECRET`, если на сервере включён `KRO_UPDATE_SECRET`.

**Анти-нулевая защита:** если цикл завершился подозрительно пустым результатом (`new_scam_channels = 0`, `losses_12h = 0`, `telegram_channels = 0`, `courses_products = 0`, `top3` пустой) и система не может подтвердить полноту широкого поиска, такой результат не публикуется на сайт и не затирает `kro-12h-stats.json`. Для диагностики сохраняется отдельный технический снимок последнего цикла, а сайт продолжает показывать данные последнего валидного обновления.

**Честный ноль:** если система подтверждает, что широкий поиск действительно завершён корректно и новых подтверждённых объектов за период нет, нулевой цикл публикуется как `honest_zero`. В этом случае на сайте показывается короткое пояснение для пользователя, а для контекста могут сохраняться данные предыдущего валидного цикла (например, `Топ-3`).

**Повторяющиеся нулевые циклы и история:** если подряд происходит несколько `suspicious_zero`, монитор запускает встроенную самопроверку (источники, парсинг, анализ) и пишет подробную диагностику в технический снимок последнего цикла и в лог. Дополнительно используется история объектов из прошлых циклов, чтобы повторяющиеся каналы и категории риска не теряли контекст даже при пустом текущем результате.

## Разовое обновление вручную (то же самое)

**Важно:** скрипты нужно запускать **из папки `backend/kro-worker`**, иначе будет ошибка «No such file or directory».

```bash
cd /Users/elizavetamedvedeva/Documents/GitHub/crypto-academy-pro/backend/kro-worker
python3 update_sources_doc_once.py
```

Или одной строкой (подставь свой путь к проекту):

```bash
cd ~/Documents/GitHub/crypto-academy-pro/backend/kro-worker && python3 update_sources_doc_once.py
```

После выполнения открой ссылку из вывода и обнови страницу (F5) в браузере.

## Расписание циклов (11:00 и 23:00 MSK)

- **Циклы:** 11:00 и 23:00 MSK (два раза в сутки).
- Документ SOURCE & DATA и отчёт **обновляются автоматически** при каждом запуске скрипта. Система **не ждёт** ответа «Готово» или «Не готово» — пайплайн выполняется без ручной проверки.
- **12:00 (день) и 00:00 (12 ночи)** — при настроенном `KRO_SITE_UPDATE_URL` данные отправляются на сайт (POST). Можно также отправить вручную.
- При желании можно проверять документ после обновления и вносить правки вручную; это **не обязательно** для работы системы.

**Cron (11:00 и 23:00 MSK = 08:00 и 20:00 UTC при MSK=UTC+3):**

```bash
0 8,20 * * * cd /path/to/backend/kro-worker && python3 run_12h_monitor.py
```

**Живой лог каждые 5 минут (00:05, 00:10, … 23:55):** чтобы в документе что-то менялось каждые 5 минут, запускай скрипт `update_live_log_5min.py` по крону. Он подтягивает счётчики (TGStat по запросу «крипто сигналы», Telega, жалобы) и обновляет в том же документе один блок памяти за последние 14 дней. Внутри этого блока каждый день идёт отдельной секцией, новая 5-минутная строка добавляется в текущий день, а дни старше 14 суток удаляются автоматически. Если плейсхолдер `События за период — ниже` пропал, восстанавливай только этот блок через `python3 fix_sources_doc_block_once.py`, а не полной перезаписью документа.

```bash
*/5 * * * * cd /path/to/backend/kro-worker && python3 update_live_log_5min.py
```

(Раз в 5 минут в любом часовом поясе; скрипт сам переводит время в MSK для подписи строки.)

## Структура документа: куда что идёт, нумерация пунктов

Когда тебе выдаётся полная информация (к 11:30 и 23:30), в документе такие блоки. Пиши правки **по номеру пункта**, чтобы было однозначно:

| Пункт | Что в документе | Куда идёт информация |
|-------|------------------|------------------------|
| **1** | Заголовок и период | Название «СКАМ-МОНИТОРИНГ \| Source & Data», период (даты/время), время формирования отчёта. |
| **2** | Живой лог | Снимок в 11:00/23:00: START, TGStat, Telega, чаты, Фильтр, Расчёт, ПОИСК ЗАВЕРШЁН. Ниже — блок памяти за последние 14 дней; внутри него `update_live_log_5min.py` каждые 5 минут обновляет текущий день и автоматически удаляет дни старше 14 суток. |
| **3** | SOURCE & DATA (полный поиск) | **3.1** — TGStat: ссылка, время, «Проверено: N каналов», по каждому каналу ✅/❌, ссылка, дата, VIP, рост, причина отклонения. **3.2** — Telega: ссылка, время, проверено каналов, по каналам. **3.3** — Чаты с жалобами: список чатов, количество жалоб, по каналам — жалобы и суммы. |
| **4** | Расчёт для сайта | Новые скам-каналы, потери за 12 ч, Telegram каналов, курсов/продуктов, ТОП-3 за сегодня (канал, сумма, статус). **Именно эти данные уходят на сайт в 12:00 и 00:00.** |
| **5** | Чеклист | Ссылки работают, каналы &lt;14 дней + VIP&gt;10к, жалобы реальные, суммы адекватны. |

Примеры формулировок для правок: «В пункте 4 исправить потери на 50 000», «В пункте 4 убрать из ТОП-3 канал @xxx», «В пункте 3.1 убрать канал @yyy», «В пункте 1 исправить период».

## API для сайта

- **POST /api/kro/update** (или **POST /api/update**)  
  Принимает JSON: `timestamp`, `new_scam_channels`, `losses_12h`, `telegram_channels`, `courses_products`, `top3_today` (массив строк). Сохраняет данные в `backend/data/kro-12h-stats.json`. Опционально: в env задать `KRO_UPDATE_SECRET` — тогда запрос должен содержать заголовок `Authorization: Bearer <секрет>` или query-параметр `secret=...`.

- **GET /api/kro/live-counter**  
  Возвращает данные для главной страницы (приоритет: чтение из `kro-12h-stats.json`, иначе из Google Sheets). Поддерживает поля `new_scam_channels`, `courses_products`, `top3_today`.

## Что нужно для обновления

1. **Актуальный код**  
   Убедись, что у тебя подтянута последняя версия из GitHub (структура: заголовок, живой лог, SOURCE & DATA 1–3, расчёт для сайта, чеклист проверки).

2. **Переменные окружения** (в `.env` в корне проекта или в `backend/kro-worker/`):
   - `KRO_SOURCES_DOC_ID` — ID документа Google Docs (из ссылки: `https://docs.google.com/document/d/**ЭТОТ_ID**/edit`).
   - `KRO_GOOGLE_CREDENTIALS_JSON` — JSON ключа сервисного аккаунта Google (или `GOOGLE_APPLICATION_CREDENTIALS` и путь к файлу ключа).
   - Для сбора жалоб из Telegram: `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`, `KRO_SOURCE_CHANNELS` (чаты через запятую).
   - Для TGStat (по желанию): настройки `tgstat_client`.
   - Опционально: `KRO_SITE_UPDATE_URL` (URL для POST после записи JSON, например `https://crypto-academy-pro.onrender.com/api/kro/update`), `KRO_SITE_UPDATE_SECRET` (если на сервере задан `KRO_UPDATE_SECRET`).

3. **Доступ к документу**  
   В Google Docs открой документ → Поделиться → добавь **email сервисного аккаунта** (из JSON ключа, поле `client_email`) с правом «Редактор».

## Таблица в конце документа (заполнение без перезаписи)

Если в документе **в конце** есть **одна таблица с 8 колонками**, скрипт **только заполнит её данными** и не будет удалять весь документ.

Колонки основной таблицы: **Объект / ссылка**, **Тип**, **Источник**, **Краткое описание**, **VIP / деньги**, **Жалобы / отзывы**, **Признаки риска (флаги)**, **Итоговый статус**. Первая строка (заголовки) не перезаписывается; заполняются только строки с данными (по одной на объект).

Допускается таблица с 7 или 9 колонками — скрипт заполнит до 8 колонок. Чтобы увидеть заполнение, запустите скрипт вручную (см. ниже) или дождитесь цикла 11:00/23:00 MSK.

## Запуск вручную (чтобы документ обновился сейчас)

Из папки проекта:

```bash
cd ~/Documents/GitHub/crypto-academy-pro/backend/kro-worker
python3 run_12h_monitor.py
```

Скрипт:
- соберёт данные из TGStat, Telega и чатов (если настроены);
- если в документе есть таблица 8 колонок в конце — **заполнит только её** (без перезаписи всего документа);
- если таблицы нет — **не должен затирать рабочий документ целиком**; сначала вставьте таблицу через `python3 insert_risk_table_into_sources_doc.py`, затем повторите обновление;
- обновит `backend/data/kro-12h-stats.json` (в т.ч. поля `new_scam_channels`, `courses_products`, `top3_today`);
- при заданном `KRO_SITE_UPDATE_URL` отправит POST на сайт.

Если скрипт запускается по крону (11:00 и 23:00 MSK), на той машине должна быть **новая версия** `run_12h_monitor.py` (деплой или git pull).
