# Что сделать, чтобы документ SOURCE & DATA обновлялся

Пошагово — что проверить и что запустить.

---

## Шаг 1. Убедись, что код актуальный

На своём компьютере в папке проекта выполни:

```bash
cd ~/Documents/GitHub/crypto-academy-pro
git pull origin main
```

Если пушила с этого же компьютера и ничего не тянешь с GitHub — этот шаг можно пропустить.

---

## Шаг 2. ID документа в .env

1. Открой свой документ SOURCE & DATA в браузере.
2. Посмотри адрес. Он такой:  
   `https://docs.google.com/document/d/XXXXXXXXXXXXXXX/edit`  
   Скопируй часть **между** `/d/` и `/edit` — это ID документа (длинная строка букв и цифр).
3. Открой файл `.env` в корне проекта (`crypto-academy-pro/.env`) или в `backend/kro-worker/.env`.
4. Найди или добавь строку:
   ```bash
   KRO_SOURCES_DOC_ID=XXXXXXXXXXXXXXX
   ```
   Вместо `XXXXXXXXXXXXXXX` вставь свой ID. Без кавычек, без пробелов. Сохрани файл.

---

## Шаг 3. Доступ Google к документу

1. Открой тот же Google Doc.
2. Нажми **Поделиться** (справа вверху).
3. У тебя должен быть ключ сервисного аккаунта Google (JSON). Открой его и найди поле **`client_email`** — там что-то вроде `kro-xxx@project-xxx.iam.gserviceaccount.com`.
4. В «Поделиться» добавь **этот email** и дай право **Редактор**.
5. Сохрани.

Если ключа ещё нет: Google Cloud Console → APIs & Services → Credentials → Create credentials → Service account → создать ключ (JSON). Скачай файл — в нём и будет `client_email`.

---

## Шаг 4. Ключ Google в .env

В `.env` должна быть одна из двух вещей:

**Вариант А.** Вся строка JSON ключа (удобно для Render/сервера):

```bash
KRO_GOOGLE_CREDENTIALS_JSON={"type":"service_account","project_id":"...","private_key_id":"...","private_key":"-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----\n","client_email":"...",...}
```

Скопируй **весь** JSON из скачанного файла в одну строку (без переносов) и вставь после `=`.

**Вариант Б.** Путь к файлу ключа на компьютере:

```bash
GOOGLE_APPLICATION_CREDENTIALS=/полный/путь/к/файлу-ключа.json
```

Сохрани `.env`.

---

## Шаг 5. Запуск скрипта

В терминале:

```bash
cd ~/Documents/GitHub/crypto-academy-pro/backend/kro-worker
python3 run_12h_monitor.py
```

Подожди, пока скрипт отработает (может быть 30–60 секунд и больше, если включён Telegram). В конце должно появиться что-то вроде:

- `Обновляю Google Doc «Источники и данные»...`
- `Готово. Документ: https://docs.google.com/...`

Если видишь ошибку — скопируй её и проверь по шагам 2–4 (ID документа, доступ, ключ в .env).

---

## Шаг 6. Проверка

Открой документ SOURCE & DATA в браузере и обнови страницу (F5). Должны появиться:

- новая дата и время в заголовке;
- блок «Источники в этом цикле» (TGStat, Telega, чаты);
- блок «Сырой поиск» (каналы TGStat, Telega, жалобы);
- блок «Итоговые значения для публикации» и ТОП‑3.

Если документ пустой или не изменился — значит, скрипт не смог в него записать. Проверь снова шаги 2 и 3 (верный ID и доступ для `client_email`).

---

## Если скрипт запускается по расписанию (cron)

Тогда он крутится на каком-то сервере или другом компьютере. Чтобы **там** в документ писалась новая структура:

- на этом сервере/компьютере нужно обновить код (git pull или новый деплой);
- в окружении этого запуска должны быть заданы те же `KRO_SOURCES_DOC_ID` и ключ Google.

После следующего запуска по расписанию документ обновится уже новым форматом.
