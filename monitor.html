03 · Таблица

База объектов

Подтверждённые объекты из scam_base: сигнал‑каналы, обменники, боты. На канал/домен — одна строка после дедупликации; сначала более свежие по дате обнаружения. Колонки повторяют поля строки; пустая ячейка («—») — нет значения в Sheets. Поиск над таблицей фильтрует строки на этой странице.

Логика записи в базу

2+ источника → объект → цитата → ссылки

Имя канала открывает ленту t.me/s в браузере (видны посты). прил. — открыть в приложении Telegram. Если экран пустой — у провайдера может быть заблокирован t.me; попробуйте VPN или другое соединение.

Как читать таблицу

Одна строка таблицы = одна запись в листе scam_base.

Строки попадают сюда после фильтров и порогов из отчёта Source & Data (вес источников, политика промо в лист и т.д.). Колонки слева направо повторяют поля записи: кто это, тип, откуда вывод, признаки, автоматический разбор, статус, число жалоб, дата.

Порядок строк: API отдаёт таблицу с сортировкой по дате обнаружения — новее выше. Номер «#» — только порядок на экране, не ID в Google Sheets. Длинные тексты в «Признаках» смотрите в подсказке ячейки (наведите курсор).

Расшифровка колонок

Объект

Имя или домен из строки. Клик по имени открывает публичную ленту t.me/s/… в браузере; иконки рядом — карточка на сайте и дополнительный URL из таблицы.

Тип объекта

Класс записи: сигнал‑канал, бот, сайт и т.д. Не путать с «Жалоб (учтено)» — это разные колонки.

Источник

Внешние ссылки из блока доказательств: статьи, чёрные списки, отзывы — всё, что обосновывает строку.

Признаки риска

Сжатые формулировки и цитаты. Полный текст чаще в подсказке ячейки — наведите курсор на строку.

Контент-анализ

Автоматическая выжимка по постам канала (если лента есть) или по сохранённым полям анализа.

Статус

Итог по правилам сводки (подтверждённый скам, риск, наблюдение…). Плашка «жалобы пользователей» — когда опорный сигнал из формы, а не только с сайта.

Жалоб (учтено)

Сводное число по строке и листам отчётов. Кружок «?» в таблице открывает пояснение методики подсчёта.

Дата

Когда запись попала в базу или дата обнаружения в источнике — в том виде, как отдал воркер.

10 · Критерии

Правила и критерии

›

Описание системы

  • Автоматический мониторинг крипто-сигнальных Telegram-каналов каждые 12 часов
  • Источники: stop-scam1.com, fin-obzor.net, cryptorussia.ru, vklader.com, форма жалоб с сайта
  • GitHub Actions запускает run_12h_monitor.py в 09:00 и 21:00 UTC (12:00 и 00:00 MSK)
  • Данные хранятся в Google Sheets (scam_base, kro_meta, kro_history)
  • Сайт читает данные напрямую из Google Sheets — переживает рестарты сервера

Уровни риска

● В РИСКЕ

≥2 жалобы от разных людей + любой из признаков: сигналы long/short, продаёт VIP, гарантирует доход, скрывает убытки, блокирует после оплаты

● ПОВЕДЕНЧЕСКИЙ РИСК

Жалоб может не быть, но канал: давит на срочность, обещает x2-x10, призывает «зайти всем депозитом», использует страх и стыд

● ПОД НАБЛЮДЕНИЕМ

Мало данных: одна жалоба, платный VIP без жалоб, новый канал без истории

Критерии попадания в базу

  • Канал упоминается на сайте-разоблачителе (stop-scam1.com, fin-obzor.net) — 1 источник
  • ≥2 жалобы от разных людей через форму жалоб на сайте → автопромоция в scam_base
  • Канал продаёт сигналы или VIP-доступ с ценой ≥10 000 ₽
  • Наличие реальных признаков мошенничества в тексте источника

Что НЕ попадает в базу

  • Новостные каналы без сигналов и продаж
  • Каналы которые честно показывают убытки и говорят о рисках
  • Каналы где одна жалоба и нет других признаков
  • Все каналы из списка исключений

Спецификация формата отчёта

  • Каждая запись в scam_base: username, ссылка t.me/username, дата обнаружения, тип объекта, цена VIP, число жалоб, сумма потерь ₽, источник, текст признаков риска, статус
  • source_evidence — конкретные факты: цитаты из статей, описания схемы. Никогда не выдуманные
  • totalLost: 0 если суммы в источнике не указаны — не скрыто, реально нет данных
  • publishStatus: valid — только когда данные реальные. honest_zero — если ничего не найдено

Структура лог-блока по дню

  • Для каждого дня — один лог-блок: Период: DD.MM.YYYY 00:00 – 23:55 (MSK)
  • Ниже — «Временная линия дня:» и строки событий по времени в возрастающем порядке от 00:00 до 23:55
  • Каждая отметка времени (HH:MM) используется не больше одного раза
  • Запрещено копировать один и тот же блок событий (03:00 с теми же каналами) многократно
  • Списки каналов не пишутся в лог по времени — только в таблице
Формат временной линии
HH:MM — краткое описание события (ОДНА строка)

Пример:
Период: 07.03.2026 00:00 – 07.03.2026 23:55 (MSK)
Время формирования: 7 марта, 23:55 MSK

Главная таблица «Объекты и риск» — 8 столбцов

№1
Объект / ссылка
@username + гиперссылка t.me/username. Нет ссылки или не крипта → строку не создавать.
№2
Тип
сигнал-канал / крипто-канал / бот / сайт-курс / обучение. Одно значение без описаний.
№3
Источник
каталог Telegram / поиск в Telegram / чат с жалобами / поиск в интернете. До двух через «+».
№4
Краткое описание
1–2 предложения по факту. Только то, что видно в описании и постах. Без оценок.
№5
VIP / тарифы
Как объект зарабатывает. Только реальные данные. «Платных услуг не обнаружено» если нет.
№6
Жалобы / отзывы
Итог по жалобам. Если сумм нет — не придумывать. «Жалоб за период не найдено» если нет.
№7
Признаки риска (флаги)
Конкретные флаги по факту: новый канал (<14 дней), дорогой VIP (≥10 000₽), обещания x2/x5, только прибыльные сделки. Нельзя придумывать.
№8
Итоговый статус
в риске / поведенческий риск / без риска / под наблюдением. Только из столбцов 4–7.

Связь документа с сайтом

  • Все цифры и объекты, выводимые на сайт, должны быть прослеживаемы до таблицы «Объекты и риск»
  • В конце блока за день — раздел: сколько строк со статусом «в риске»; суммарные зафиксированные потери; какие объекты в топ-3
  • Никаких чисел «из воздуха» — всё только из таблиц
  • Приоритет поиска — сигнал-каналы по крипте; новости/аналитика без продаж не считаются рисковыми
